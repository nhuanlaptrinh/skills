# OpenClaw Telegram Customer Inbox

Install the reusable staff-group routing workflow for an existing OpenClaw Telegram account. The workflow uses one existing OpenClaw polling process and a local plugin; it must not create a second Telegram polling worker.

## Required inputs

Confirm these values before mutation:

- OpenClaw root and runtime workspace path.
- Existing Telegram account ID and a configured `tokenFile` (never request or print the token value).
- Telegram staff supergroup ID. If Telegram migrated a group, use the current `-100...` ID.
- Exact positive numeric Telegram user IDs allowed to operate the inbox.
- Optional display name such as `Mia` or the business name.

Do not use `*` for staff IDs, group `allowFrom`, takeover authorization, or button authorization. Do not print tokens, full secret-bearing config, cookies, or raw state.

## Behavior contract

- Customer DM: mirror to the staff group as `🔵 LUỒNG KHÁCH HÀNG` and preserve a reply mapping.
- AI answer: mirror as `🤖 LUỒNG <brand> / AI`.
- Normal staff reply: send to that customer as `🟢 LUỒNG NHÂN VIÊN → KHÁCH`; AI remains active.
- `🟡 Tiếp quản khách này`, `/takeover`, or `Tiếp quản`: pause AI only for that customer.
- `🟢 Trả lại bot`, `/bot`, or `Trả lại bot`: resume AI for that customer.
- Staff replies are accepted only when they reply to a mapped customer, AI, staff acknowledgement, or state notice. The plugin stores mappings in a root-only state file.

## Install on another VPS

Read the target's applicable `AGENTS.md` first. Back up the OpenClaw configuration and existing plugin before changing production. Run the bundled installer from this skill:

```bash
python3 /path/to/openclaw-telegram-customer-inbox/scripts/install_customer_inbox.py \
  --openclaw-root ~/.openclaw \
  --workspace ~/.openclaw/workspace \
  --account-id <telegram-account-id> \
  --group-id <telegram-supergroup-id> \
  --staff-id <staff-user-id-1> \
  --staff-id <staff-user-id-2> \
  --brand-name <brand-name> \
  --dry-run
```

Review the dry run, then rerun with `--apply`. The installer:

- Copies the bundled plugin to `workspace/plugins/telegram-customer-inbox`.
- Adds one `plugins.entries.telegram-customer-inbox` entry and one plugin load path.
- Configures the account's group with `requireMention: false` and the exact staff allowlist.
- Enables Telegram group inline buttons for the account.
- Creates a root-only backup and leaves token configuration untouched.

Use `--state-file` only when the target has a deliberate state location. Use `--backup-dir` when the host has a standard backup policy. `--check` is read-only and fails if config or plugin files differ from the bundled template.

## Verify and activate

After apply:

```bash
openclaw config validate
python3 /path/to/openclaw-telegram-customer-inbox/scripts/install_customer_inbox.py \
  --openclaw-root ~/.openclaw \
  --workspace ~/.openclaw/workspace \
  --account-id <telegram-account-id> \
  --group-id <telegram-supergroup-id> \
  --staff-id <staff-user-id-1> \
  --check
systemctl --user restart openclaw-gateway.service
systemctl --user is-active openclaw-gateway.service
journalctl --user -u openclaw-gateway.service --since '2 minutes ago' --no-pager | grep -i 'telegram-customer-inbox'
```

Confirm the bot is a member of the group and can send messages and pin the legend. Send a non-secret legend to the group and pin it only after verifying the group ID. Do not send live customer test messages unless the user explicitly asks; prefer checking config, plugin load, service health, and local simulations.

## Existing state and migration

Never blindly clear a paused customer. If an older installation paused customers automatically after every staff reply, inspect the state and reset only those known legacy auto-pauses; preserve an intentional takeover. Keep `stateFile` mode `0700` for its directory and `0600` for its JSON file.

## Repair rules

- If customer messages mirror but AI does not answer, inspect `paused` state and the `before_dispatch`/`message_sending` hooks before changing routing.
- If staff replies do not route, verify the reply is to a mapped group message and the sender ID is in the exact allowlist.
- If the button is missing, inspect the account's inline-button capability and confirm new mirror messages are being generated by the plugin.
- If a button click is ignored, verify the current supergroup ID, exact staff authorization, callback namespace, and that the message still has a mapping.
- Do not add another polling daemon or modify the bot token during routine repair.

## Rollback

Stop before rollback if current files differ from the installer backup. Restore the backed-up OpenClaw JSON and plugin directory, validate config, restart the Gateway, and preserve the state file unless the user explicitly requests state rollback.
